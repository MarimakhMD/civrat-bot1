# CIVRAT Internationalization Contract

## Supported locales

The initial supported guild locales are `fr` and `en`. The locale contract is
explicit and intentionally small so that new locales can be added without
changing command or service logic.

## Usage

Future modules must use translation keys through a context-bound translator:

```js
context.t("errors.authorizationDenied");
context.t("tickets.created", { channel: "#ticket-0001" });
```

Future module logic must not embed user-facing French or English sentences.

## No cross-language fallback

CIVRAT never falls back from one supported language to another. A missing key
is a development error and the translation parity test fails before delivery.
This prevents a French guild from receiving English text, and the reverse.

An invalid or absent persisted guild locale resolves to the configured default
locale, currently French. This is a locale-validation policy, not a fallback
between translation dictionaries.

## Translation parity

Every locale must expose the same nested keys and interpolation variables as
the reference locale. The core validator checks this contract in offline tests.
