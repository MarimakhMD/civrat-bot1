## Cohérence dépôts / services / RPC / contraintes / RLS / config

- **Repositories JS → RPC** : `SupabaseTicketFreeCategoryRepository.save` → `civrat_ticket_free_save_category` ; `SupabaseTicketRepository.createCategoryTicket` → `civrat_ticket_free_create_snapshot` ; `SupabaseTicketHistoricalAttestationRepository` → `civrat_ticket_historical_attest/refusal` ; `SupabaseTicketOperationRepository` → `civrat_ticket_operation_begin/transition/participant_confirm/creation_confirm/list_unresolved` ; `SupabaseTicketReservationRepository` (04+07) → `civrat_ticket_reserve_open/finalize/cancel/reserve_reopen` + `listPending/tryLock` (réconciliation, fallback advisory) + `civrat_ticket_lease_reservation/release_lease/renew_lease` (lease durable, ownerId+TTL) ; `SupabaseTicketCounterRepository` (06) → `increment_ticket_counter` (compat) + `civrat_ticket_reserve_number` (idempotent, `next(guildId, operationId)`) + `civrat_ticket_counter_init` (précontrôle).
- **Compteur idempotence** : `civrat_ticket_number_reservations(operation_id PK, guild_id, ticket_number UNIQUE)`, advisory lock `civrat-ticket-number:guild` + `operation_id` unique → même `operationId` rejoué = même `ticket_number`, jamais incrémenté à nouveau ; protection concurrence via `pg_advisory_xact_lock` + `ON CONFLICT DO NOTHING` ; compteur commun Free/Premium (`guild_configs.ticket_counter` unique, format public `ticket-001` inchangé, aucun `tkt-`).
- **Précontrôle numérotation** : `guild.channels` n'est PAS une table Supabase (vérifié `to_regclass` null) — inventaire Discord par `guild.channels.fetch()` → `^ticket-\d+$` → `maxExisting` → `civrat_ticket_counter_init(guild_id, max)` avec `GREATEST` et lock `civrat-ticket-counter-init:guild` ; jamais de diminution. Script `scripts/precontrol-ticket-counter.js` : `parseArgs/isValidGuildId/extractTicketNumber/fetchDiscordMax/readCounter/runPrecontrol` (dry-run défaut, `--apply` explicite, erreurs Discord vs Supabase distinguées, jamais token loggé, init atomique `GREATEST` + `pg_advisory_xact_lock`, format public `ticket-001`).
- **Worker réconciliation** : 1 process / 1 interval 15 min après `client.ready`, aucun cron par guilde/interaction, idempotent, `start`/`stop` propres (SIGINT/SIGTERM + `unref`), singleton `getTicketReconciliationRuntime` (ownerId `civrat-worker-uuid-pid`, 300 s TTL, `global.__CIVRAT_*` anti-double-start, non dupliqué avec `createGuildSettingsRuntime`), coordination multi-process via lease durable `locked_by/expiration` (RPC 07) + fallback advisory 06, reprise après redémarrage (réservations `reserved/external_pending/channel_known/cleanup_pending` conservées).
- **Vérif salons** : `client.channels.fetch` ne transforme jamais erreur réseau/timeout/permission (50001 Missing Access, 50013, 429, 5xx) en preuve absence ; seuls `Unknown Channel 10003` (+404) = `discordExists=false` prouvé ; autre = `null` incertain → `uncertain` conservé, annulation seulement si `discordExists===false && ticketExists===false` prouvés, sinon `uncertain`.
- **Compteur idempotence** : voir 06 ; migration additive `ADD COLUMN IF NOT EXISTS` + `UPDATE … WHERE IS NULL` sans écraser, compteur commun Free/Premium, `operation_id` unique + `pg_advisory_xact_lock` + `ON CONFLICT DO NOTHING` + re-lecture après lock, précontrôle `GREATEST` jamais diminuer, protection création simultanée pendant init.
- **Contraintes** : `CHECK (open_limit BETWEEN 1 AND 5)` sur settings/catégories/tickets.free_open_limit ; `CHECK (cardinality(support_role_ids) BETWEEN 1 AND 5)` ; `CHECK (destination_id ~ '^[0-9]{15,22}$')` ; `UNIQUE (guild_id, id)` catégories ; `PRIMARY KEY (guild_id, channel_id, member_id)` participants ; `UNIQUE (operation_id, revision)` events ; `CHECK (state IN (...))` partout.
- **Index** : `civrat_ticket_free_categories_guild_idx`, `civrat_ticket_operations_unresolved_scope_idx` (scope unique partiel), `civrat_ticket_operations_recovery_idx`, `civrat_ticket_historical_refusals_guild_idx`, `idx_tickets_open_unique` (historique, conservé).
- **RLS** : toutes les tables Tickets Free `ENABLE ROW LEVEL SECURITY` sans policy publique ; `REVOKE ALL` PUBLIC/anon/authenticated ; `GRANT SELECT` (+ INSERT/UPDATE settings) à `service_role` seulement ; RPC `SECURITY DEFINER` avec `search_path = pg_catalog, public`.
- **Config** : `TicketConfigKey.ENABLED/CATEGORY_ID/SUPPORT_ROLE_ID/LOG_CHANNEL_ID/TRANSCRIPT_ALLOWED_*` → `guild_configs` (legacy). Limite globale `open_limit` → `civrat_ticket_free_settings` (04) + `TicketFreeSettingsRepository`. Limite catégorie `open_limit nullable` → `civrat_ticket_free_categories.open_limit`.

**Aucune validation PostgreSQL n'est présentée comme preuve** : les tests JS utilisent des doublures et vérifient uniquement les signatures d'appel.
